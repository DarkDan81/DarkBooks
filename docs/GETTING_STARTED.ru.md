# Первая книга с иллюстрациями

[Главная](README.ru.md) · [English](GETTING_STARTED.md)

## 1. Запуск

Скачайте [DarkBooks-Windows-x64.zip](https://github.com/DarkDan81/DarkBooks/releases/latest/download/DarkBooks-Windows-x64.zip),
распакуйте **всю папку** в доступное для записи место и откройте **Start.cmd**.
Не запускайте изнутри ZIP. Браузер откроется автоматически. Окно запуска оставьте
открытым, пока пользуетесь приложением. Для русского интерфейса нажмите **РУ**.

Python включён в архив. Модели подключаются отдельно:

| Режим | Что нужно |
|---|---|
| Локальный | LM Studio для текста, ComfyUI для картинок, веса моделей |
| Облачный | Совместимые текстовый и image API, адреса, названия моделей, ключи |
| Смешанный | Одна модель локально, другая в облаке |

## 2А. Локальные модели

### LM Studio: текст

1. Установите [LM Studio](https://lmstudio.ai/).
2. Скачайте и загрузите модель. В наших экспериментах использовалась
   [Qwen3.5-9B GGUF](https://huggingface.co/lmstudio-community/Qwen3.5-9B-GGUF),
   файл `Qwen3.5-9B-Q6_K.gguf`. Можно пробовать другие модели, умеющие выдавать JSON.
3. На вкладке **Developer** запустите сервер. Скопируйте его адрес.
4. В DarkBooks откройте **Подключения → Текстовая модель**.
5. Для стандартного локального порта адрес — `http://127.0.0.1:1234/v1`.
6. Нажмите **Найти модели** и выберите загруженную модель в поле «Модель».
   Ключ для локального сервера обычно не нужен, если вы не включили авторизацию.

Если обе модели используют одну видеокарту, можно включить **Расширенные настройки →
Автоматически загружать и выгружать через LM Studio**. Команда `lms` должна быть
доступна, а ключ модели — совпадать с ключом скачанной модели. После анализа
DarkBooks выгрузит текстовую модель перед генерацией картинок. Если управляете
памятью сами, оставьте эту опцию выключенной.

[Официальная инструкция LM Studio](https://lmstudio.ai/docs/developer/core/server).

### ComfyUI: картинки

1. Установите и запустите [ComfyUI](https://docs.comfy.org/installation/desktop/windows).
2. Для встроенного пресета нужна версия с узлом **TextEncodeQwenImage21**.
   Сторонние custom nodes для этого пресета не требуются.
3. Скачайте файлы из [Comfy-Org/Qwen-Image-2.1](https://huggingface.co/Comfy-Org/Qwen-Image-2.1):

| Файл | Папка в ComfyUI |
|---|---|
| `qwen_image_2.1_turbo_int8_convrot.safetensors` | `models/diffusion_models/` |
| `qwen3vl_8b_w4a8.safetensors` | `models/text_encoders/` |
| `qwen_image_2.1_vae_bf16.safetensors` | `models/vae/` |

Прямые ссылки на файлы есть в [английской инструкции](GETTING_STARTED.md#images-comfyui).

4. Перезапустите ComfyUI после добавления файлов.
5. В DarkBooks выберите **ComfyUI** и адрес своего сервера, например
   `http://127.0.0.1:8188`. В Desktop и нестандартных установках порт может отличаться —
   скопируйте адрес своей установки.
6. Нажмите **Проверить**. Выберите checkpoint в поле «Модель», а в «Файлы моделей
   ComfyUI» — энкодер и VAE из таблицы. Сохраните подключения.

Встроенный пресет использует 8 шагов и картинки 1024 пикселя. Наши локальные
эксперименты проводились на RTX 5060 Ti с 16 ГБ VRAM и 32 ГБ RAM. Это проверенная
конфигурация, а не универсальные требования ко всем моделям. Веса скачиваются
отдельно и имеют свои лицензии.

При ошибке отсутствующего узла обновите ComfyUI или используйте подходящий
workflow. Для другой архитектуры недостаточно поменять имя checkpoint.

### Другой workflow

До первого запуска издания откройте **Параметры издания → Свой ComfyUI workflow**.
Экспортируйте workflow из ComfyUI в **API-формате**, выберите JSON и задайте
привязки узлов. Пример для встроенного пресета:

```json
{"bindings":{"prompt":["6","prompt"],"seed":["3","seed"],"references":[]},"output_node":"9"}
```

Замените ID на соответствующие вашему графу. Выходной узел должен возвращать одну
картинку. Файлы весов и параметры sampler в своём workflow задаются в его JSON;
настройте их в ComfyUI до экспорта.

## 2Б. Облачные API

Локальные веса и видеокарта не нужны.

1. Получите у провайдера базовый адрес API, имя модели и ключ. Подписка на обычный
   чат не обязательно даёт доступ к API.
2. Заполните адрес, модель и ключ текстового сервиса. Добавьте `/v1`, если это
   часть адреса вашего API.
3. Нужны Chat Completions и структурированный JSON. Если JSON Schema не
   поддерживается, выберите JSON Object в расширенных настройках.
4. Для картинок выберите **Совместимый image API · облако**, введите адрес,
   имя рисующей модели и ключ. Укажите поддерживаемый сервисом размер.
5. Сохраните настройки и проверьте на пробной главе.

Текстовый адаптер использует `POST /chat/completions`. Рисующий адаптер ожидает
`POST /images/generations` с `model`, `prompt`, `n`, `size` и ответом
`data[0].b64_json` или `data[0].url`. Сервису с другим API потребуется свой адаптер.
Проверка image-подключения не запускает платную генерацию.

Облачные провайдеры отдельно не сертифицировались. Запросы могут стоить денег;
автоматического расчёта стоимости пока нет. Начните с одной главы.

## 3. Пробное издание

1. В библиотеке нажмите **Добавить книгу** и выберите `.fb2`. Кнопка «Открыть пример»
   загрузит оригинальный короткий рассказ *The Lantern Keeper* для проверки.
2. Коротко опишите **Мир и атмосферу**, например: «Старый прибрежный город,
   маяки, тихая тайна, поздняя осень».
3. Выберите стиль. По умолчанию это чёрно-белые книжные рисунки тушью.
4. Выберите главы и число картинок. Для начала достаточно двух-трёх. Если
   подходящих сцен меньше, глава получит меньше иллюстраций.
5. Для книги от первого лица можно указать имя рассказчика — оно будет связано
   с «Я» / «I».
6. Нажмите **Попробовать главу**. Отдельное пробное издание обработает первую
   выбранную главу; исходный проект останется для полного запуска.

Понравился результат — вернитесь к исходному проекту и нажмите «Иллюстрировать главы».

## 4. Остановка и результат

Кнопка **Остановить** завершает и сохраняет текущую операцию. Запрос или картинка
может выполняться некоторое время — дождитесь статуса «На паузе». После этого
можно нажать «Продолжить».

Закрытие вкладки не останавливает worker. После сбоя откройте приложение и
продолжите издание. Завершённые шаги используются повторно; незавершённая операция
может повториться. Продолжения с конкретного шага sampler нет.

Готовую FB2 можно скачать для читалки, а картинки — отдельно ZIP. Вся книга
сохраняется, даже если обработаны только некоторые главы. В FB2 иллюстрации
чёрно-белые, в ZIP — исходные генерации.

Параметры начатого издания зафиксированы. Для другой модели или промпта добавьте
книгу как новый проект.

## Если что-то не работает

- **Нет связи с моделью:** запустите сервер, проверьте адрес и порт. `localhost`
  означает этот компьютер.
- **Не хватает памяти:** выгрузите текстовую модель или перенесите одну из моделей
  в облако/на другую машину. Можно включить управление LM Studio.
- **Есть только EPUB/PDF:** эта версия работает с FB2. Предварительно конвертируйте
  книгу привычным вам инструментом.
- **Разные лица:** это известное ограничение генерации. Автоматической замены лиц
  в веб-версии нет.
- **Где файлы:** в `data` рядом с portable-приложением; при установке через pip
  возможна папка `~/DarkBooks`. Переменная `DARKBOOKS_DATA` меняет путь.
- **Где ключи:** в открытом виде в локальных настройках. Не публикуйте заполненную
  папку `data`.
- **Другой вопрос:** откройте журнал и создайте
  [issue](https://github.com/DarkDan81/DarkBooks/issues/new/choose), указав версию,
  модели и ошибку. Не прикладывайте свои ключи и полную книгу.
